# 新页面 UI 一致性审查（2026-11-19）

> 状态：审查完成；后续已修复插件 TopAppBar、更多缺失入口、时间表课表设置、
> 课程池基础能力；HITA-Android 主页面像素级残差（今日 hero、资讯/时间表）仍未全量复核。
> 原文保留为审查基线。2026-11-19 复审见 `docs/plans/2026-11-19-pixel-audit.md`：
> 抽屉已补尺寸/像素证据；成绩页 TopAppBar 已补，但整体差异 9.941%，仍未通过。  
> 基准：HITA-L ↔ HITA_L 1.5.3；HITA-Android ↔ HITA_Android 3.1.2  
> 已有证据：`docs/porting-status.md`、`docs/evidence/7.1/2026-11-18/report.md`

## 1. 审查口径

“新页面”定义为 **HITA_L 1.5.3 中不存在的页面**：

- HITA-Android 的 6 个 Shell 页面（参考是 HITA_Android 3.1.2，不是 HITA-L）；
- 宿主自建页面：插件市场、插件容器、Shell 资讯详情/门户登录、预设迁移/小组件配置；
- 插件内容页：成绩分析、外观与字体、培养方案；
- 从参考工程迁入插件模块的 `TimetableManager`、`TimetableDetail`、`Exam`、
  `ScoreInquiry`、`EmptyClassroom`、`Search`、`ShenzhenWebLogin` 等，页面源不变，
  不按“新 UI”计数。

本轮新打开/新纳入审查的页面共 **17 个页面或页面组**：

| 类别 | 页面 |
|---|---|
| HITA-Android Shell | 待办、今日、时间表、助手、资讯、更多（6） |
| 宿主自建 | 查询并下载、我的插件、自定义插件指北、PluginUiActivity、资讯详情、门户登录、预设迁移、小组件配置（8） |
| 插件内容 | 成绩分析、外观与字体、培养方案（3） |

## 2. 逐类结论

### 2.1 HITA-L：达到一致

现有同数据、同 hint、同系统栏像素证据：

| 页面 | 差异 |
|---|---:|
| 今日 | 0.55% |
| 时间表 | 0.53% |
| 功能中心 | 0.47% |

底栏已在 `979cf12` 从自绘 `DynamicBottomBar` 恢复为参考的
`SmoothBottomBar + main_bottom_nav_menu`，并固定 3 页；主路径达到一致。

HITA-L 的新增页面为 0；其余子页面直接复用参考 Activity/Fragment，UI 源一致，
本轮没有重新做像素验收。

### 2.2 HITA-Android：部分一致，整体未通过

已有内容区数据（top 130 / bottom 310，等价数据态）：

| 页面 | 差异 | 结论 |
|---|---:|---|
| 待办 | 0.792% | 内容通过；header 2.12%、dock 8.48% 未过 |
| 今日 | 1.733% | 内容通过；当前课程 hero 与上游不同 |
| 助手 | 0.934% | 内容通过 |
| 时间表 | 11.46% | 未通过 |
| 资讯 | 11.49% | 未通过 |
| 更多 | 6.25% | 未通过，且有结构缺口 |

审查中确认的具体 UI/结构差异：

1. **今日**：上游在有进行中课程时显示课程 hero（课程名、进行中、进度）；
   当前 Shell 固定显示“今日课程 / 继续加油”插画头卡。数据态不同，但 hero 结构未对齐。
2. **时间表**：上游右上角是“分享与好友 / 课表设置”；当前是“分享课表 / 切换深浅色”，
   缺“课表设置”。表头课表名/学期 chip 也与上游不同。
3. **更多**：上游有“提交课程资料 PR、实用网址、课程提醒、实时课程、使用统计、公告”；
   当前 Shell 缺少这些入口/开关。“深圳课程浏览”因插件缺失被隐藏。
   上游右上角菜单打开抽屉；当前 Shell 的同位置图标打开插件市场。
4. **资讯/时间表**：已有 11% 级内容差异，尚未达到一致标准。

### 2.3 宿主自建页面：多数没有上游基准

| 页面 | UI 一致性结论 |
|---|---|
| 插件市场 3 tab | 上游不存在；只能评价“内部一致”：使用宿主同一套主题 token/Material 卡片。不能称为与参考一致 |
| 整合包预览/来源选择 | 同上，属于宿主产品页面，无参考 |
| PluginUiActivity | **不一致**：没有参考页面常见的 TopAppBar/返回键，插件正文从屏幕顶部直接开始 |
| Shell 资讯详情 | 未做像素对比；与上游 `BlogReaderActivity` 的 AppBar/标题结构不同 |
| Shell 门户登录 | 宿主自建；未做像素对比 |
| 预设迁移/小组件配置 | 工具/系统页面，无参考；本轮只做入口检查 |

### 2.4 插件内容页：成绩页明确不一致

| 页面 | 对照 | 结论 |
|---|---|---|
| 成绩分析 | 上游“个人成绩明细”=`ShenzhenGradeAnalysisActivity` | **不一致**：上游有 TopAppBar（返回、标题、刷新）和“请先连接深圳 Web 教务”卡片；当前插件页无 TopAppBar/返回，标题与空态布局不同 |
| 外观与字体 | 上游无独立同名页面 | 无参考；宿主内部风格一致 |
| 培养方案 | 上游需 Web 登录 | 未取得等价页面，不能判定一致 |

### 2.5 参考页迁入插件：结构一致，未重新像素验收

`TimetableManager`、`TimetableDetail`、`Exam`、`ScoreInquiry`、`EmptyClassroom`、
`Search`、`ShenzhenWebLogin` 的页面源来自参考工程，迁入时只改了 R/依赖注入；
设备验证入口、首屏和按钮可用。未重新做逐页像素对比，因此只能记为
“结构一致”，不能记为“UI 完全一致”。

## 3. 结论

- **HITA-L：是**。3 个主页面 0.47%–0.55%，底栏已恢复参考实现。
- **HITA-Android：否**。待办/今日/助手仅内容区通过；时间表、资讯、更多未通过，
  且更多存在缺失入口、时间表缺“课表设置”、今日 hero 结构不同。
- **新增宿主/插件页面：多数未达到一致**。插件市场属于无参考的宿主产品页；
  `PluginUiActivity` 和成绩页缺少参考页的 TopAppBar/返回结构。

## 4. 后续修复优先级

1. 给 `PluginUiActivity` 增加统一的 TopAppBar/返回，并让成绩/外观/培养方案页适配；
2. 恢复 HITA-Android 更多页缺失入口/设置开关，明确“深圳课程浏览”插件策略；
3. 时间表补“课表设置”，对齐右上角动作；
4. 今日补“进行中课程”hero；
5. 再对时间表/资讯/更多做等价数据态像素验收。
